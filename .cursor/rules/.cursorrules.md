## What This App Does

This application enables project managers to perform data-driven capacity and portfolio
planning by aligning team availability with required skills and project demand. It provides
clear visibility into who can work on what and when, ensuring optimal resource allocation
and realistic delivery timelines.

**Primary user:** Project Manager at Mileway BV (VS Finance team)
**Stack:** React 19 + TypeScript + Vite + Tailwind CSS + Zustand + Supabase

---

## How to Run It

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173

npm run test:run     # run tests once
npx tsc --noEmit     # type check — run this before every commit
```

Needs `frontend/.env.local` with `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
Without it, the app runs in local-only mode — fine for UI work.

## The One Concept You Must Understand

Every item in the hierarchy — Epic, Feature, Story, UAT, Hypercare — has **two tracks**:

- **IT track** (blue #0089DD — Mileway Light Blue): developers, BAs, architects from Jira
- **BIZ track** (grey #6C7A89 — Mileway Cool Grey): Finance/Operations contacts with their own capacity

Both tracks carry equal weight. Both consume capacity. Both appear in every view.
Distinguish them with labels ("IT" / "BIZ") and subtle tints — not competing colours.
**If you build something that only handles one track, it is incomplete by definition.**

## Rules (only 5 — each one exists because something broke)

**1. No text inside Gantt bars.**
Bars are coloured rectangles only. All detail is in the slide-out panel.

**2. Gantt bar positions are percentage-based, never grid-based.**
Use `position: absolute` with `left` and `width` as percentages. Never CSS grid for bars.

**3. Never set `overflow: hidden` on a Gantt row.**
Continuation arrows are CSS pseudo-elements that render outside bar bounds.
This silently breaks them and is very hard to debug.

**4. Every Zustand selector returning an array or object must use `useShallow`.**
React 19 will infinite-loop without it. No exceptions.

**5. Never edit an existing migration file.**
Add a new one: `supabase/migrations/NNN_description.sql`. Increment the number.
